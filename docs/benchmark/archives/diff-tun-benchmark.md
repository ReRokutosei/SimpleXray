# SimpleXray TUN 跨设备差异分析

本文比较骁龙 778G 与第五代骁龙 8 至尊版上的四种 TUN 后端。完整数据、图表和设备报告保存在对应目录。

- [骁龙 778G](./qualcomm-snapdragon-778g/report/android-tun-benchmark.md)
- [第五代骁龙 8 至尊版](./qualcomm-snapdragon-8-elite-gen-5/report/android-tun-benchmark.md)

## 1 数据可比性

两套数据均覆盖 Wi-Fi、USB、回环、TCP、UDP、单流、多流、空闲连接、受载时延和 60 秒持续传输。跨设备比较只在测量口径一致时成立。受载时延和 60 秒持续吞吐还会受到无线链路、空口调度、终端节能和温控状态影响，不能单独归因于协议栈实现。内存斜率来自隔离微基准，两份设备数据目录中的结果一致。

## 2 Wi-Fi TCP 下行吞吐

表中为 5 秒标准测试的三轮平均值，单位为 Mbps。单元格内为单流与八流结果。

| 后端 | 骁龙 778G | 第五代骁龙 8 至尊版 |
| :--- | :---: | :---: |
| 物理直连 | 758.0 / 771.5 | 756.4 / 807.9 |
| HEV | 504.3 / 281.6 | 714.1 / 797.0 |
| SingTUN | 186.3 / 810.1 | 680.6 / 786.8 |
| MipsTUN | 238.6 / 125.4 | 717.5 / 805.6 |
| Xray Native TUN | 185.4 / 513.9 | 710.7 / 756.2 |

旗舰平台缩小了协议栈与物理直连之间的单流差距。HEV、MipsTUN 和 Xray Native TUN 的单流下行分别达到 714.1、717.5 和 710.7 Mbps，SingTUN 从 186.3 提升到 680.6 Mbps。八流结果仍由数据路径和调度方式决定，SingTUN、MipsTUN 和 HEV 接近物理直连，Xray Native TUN 为 756.2 Mbps，低于物理直连的 807.9 Mbps。

中端平台上 HEV 的八流结果为 281.6 Mbps，MipsTUN 为 125.4 Mbps，Xray Native TUN 为 513.9 Mbps，SingTUN 为 810.1 Mbps。该分化说明单线程处理、Go 运行时调度和 gVisor 数据路径在高并发下仍存在明显差异。旗舰平台缓解了单核算力不足，但没有消除多流调度和内存拷贝开销。

## 3 受载时延膨胀

表中为八流 TCP 下行时的时延膨胀，单位为毫秒。两代设备均使用经过同一 TUN 路径的 TCP echo 探针，骁龙 778G 数值为 3 轮实测算术平均，旗舰机为单轮实测值。

| 后端 | 骁龙 778G | 第五代骁龙 8 至尊版 |
| :--- | ---: | ---: |
| 物理直连 | +74.3 | +72.3 |
| HEV | +29.7 | +35.9 |
| SingTUN | +59.7 | +33.4 |
| MipsTUN | 未观测到额外膨胀 | +86.6 |
| Xray Native TUN | +34.8 | +87.3 |

探针口径统一后，两代设备的受载时延可以直接比较。骁龙 778G 上 MipsTUN 的八流下载吞吐只有约 118 Mbps，受载 RTT 中位数不高于空载，未形成明显排队。Xray Native TUN 为 +34.8 ms，HEV 为 +29.7 ms，SingTUN 为 +59.7 ms。

旗舰平台上 HEV 为 +35.9 ms，SingTUN 降到 +33.4 ms。MipsTUN 和 Xray Native TUN 分别为 +86.6 ms 和 +87.3 ms，明显高于中端平台。算力提升没有普遍消除队列膨胀，MipsTUN 与 Xray Native TUN 的队列管理、锁竞争、内存拷贝和事件调度仍是主要风险。

## 4 60 秒持续传输

表中为八流 TCP 下行持续传输结果。变异系数由 60 个吞吐采样点计算，末段变化为末 5 秒平均吞吐相对前 5 秒平均吞吐的变化率。正值表示末段上升，负值表示末段下降。

| 后端 | 骁龙 778G 平均吞吐 | 骁龙 778G 变异系数 | 骁龙 778G 末段变化 | 第五代骁龙 8 至尊版 平均吞吐 | 第五代骁龙 8 至尊版 变异系数 | 第五代骁龙 8 至尊版 末段变化 |
| :--- | ---: | ---: | ---: | ---: | ---: | ---: |
| 物理直连 | 704.0 | 19.65% | +26.1% | 459.7 | 13.06% | -16.5% |
| HEV | 726.0 | 19.67% | +6.5% | 511.7 | 16.74% | +40.1% |
| SingTUN | 814.3 | 10.24% | +36.2% | 587.0 | 4.40% | -5.6% |
| MipsTUN | 855.1 | 6.25% | +7.1% | 559.2 | 15.72% | +14.7% |
| Xray Native TUN | 856.1 | 8.80% | +1.3% | 557.8 | 19.15% | -39.1% |

60 秒测试不是受控的跨设备协议栈性能比较。旗舰机物理直连平均吞吐为 459.7 Mbps，低于同一设备的四个代理后端，说明该测试的主要限制不在 TUN 数据路径或处理器算力，而在无线链路或终端状态。旗舰机在 5 秒标准测试中的物理直连下行达到 807.9 Mbps，说明空口具备更高能力，60 秒均值下降属于持续负载下的链路或终端行为。骁龙 778G 的较高长跑均值同样受到链路状态影响。该表只用于比较同一设备内各后端的波动和末段趋势，不能据此判断两台设备协议栈的快慢。

旗舰平台上 SingTUN 的变异系数最低，为 4.40%，吞吐波动最小。HEV 和 MipsTUN 的末段变化较大，Xray Native TUN 末段下降 39.1%，持续负载下的稳定性仍需单独优化。骁龙 778G 的 SingTUN、MipsTUN 和 Xray Native TUN 平均吞吐均超过 810 Mbps，接近或超过该设备的 5 秒物理直连基线，说明长跑结果受链路状态和采样时点影响明显。

## 5 内存斜率与进程边界

表中为隔离微基准测得的每连接内存增长，单位为 KiB/conn。两份设备数据目录中的结果一致。

| 后端 | TCP | UDP |
| :--- | ---: | ---: |
| HEV | 12.59 | 16.59 |
| SingTUN | 52.14 | 45.84 |
| MipsTUN | 52.66 | 113.88 |
| Xray Native TUN | 63.54 | 57.55 |

连接驻留内存主要由协议栈数据结构、缓冲区和运行时分配策略决定，芯片性能不会改变其基本斜率。HEV 使用 C/lwIP，开销最低。SingTUN 和 MipsTUN 使用 Go 运行时，每个连接需要承担 goroutine、缓冲区和调度结构开销。MipsTUN 的 UDP 斜率最高，与其 BBRv3 环形缓冲区分配有关。Xray Native TUN 使用 gVisor，连接控制块和缓冲区开销偏高。

Xray Native TUN 的主进程增长较小，但真实协议栈开销位于独立子进程中，必须结合进程隔离架构解释。SingTUN 和 MipsTUN 在 Android 宿主进程中的增量会受到 Go 垃圾回收稳态影响，不能直接等同于纯协议栈开销。

## 6 结论

1. HEV 的单线程处理路径在中端平台上首先表现为单流吞吐受限，在旗舰平台上转化为受载队列和长跑波动问题。
2. SingTUN 的单流瓶颈主要受 Go 用户态协议栈处理能力影响，旗舰平台上该瓶颈大幅缓解，但运行时处理器成本仍高于 HEV。
3. MipsTUN 的 UDP 内存斜率最高，多流时延膨胀明显，BBRv3 缓冲区和并发调度仍是主要风险点。
4. Xray Native TUN 的主进程隔离有效降低了宿主进程内存增长，但 gVisor 数据路径仍有较高处理器成本，持续传输末段衰减也需要单独处理。
5. 60 秒持续吞吐的跨设备差异主要由无线链路和终端状态决定，现有数据不足以将旗舰机较低的长跑均值归因于协议栈实现。

## 7 数据目录

每个设备目录均包含以下内容。

- `data/` 保存端到端测试、持续传输和独立微基准原始数据。
- `charts/` 保存对应设备的图表。
- `report/` 保存只针对该设备的完整报告。

跨设备结论只维护在本文档中，设备报告不互相引用。
